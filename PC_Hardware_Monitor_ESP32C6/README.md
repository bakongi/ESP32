# 🖥️ ESP32-C6 PC & Board Hardware Monitor

Система аппаратного мониторинга реального времени для платы **Waveshare ESP32-C6-LCD-1.47** с IPS экраном 172×320. 

Проект включает в себя 3-экранную прошивку с плавной анимированной графикой (30 FPS) и сверхлегкое нативное приложение для Windows (**116 КБ**), работающее в системном трее возле часов.

---

## 🌟 Основные возможности

- **3 Интерактивных экрана** (переключение коротким нажатием кнопки `BOOT` на плате):
  - **Экран 1 (`P1/3 [CPU]`):** Загрузка процессора ПК (%), Температура CPU ПК (°C), Загрузка OЗУ ПК (%).
  - **Экран 2 (`P2/3 [GPU]`):** Загрузка видеокарты ПК (%), Температура GPU ПК (°C), Загрузка видеопамяти VRAM (%).
  - **Экран 3 (`P3/3 [ESP]`):** Нагрузка процессора платки ESP32-C6 (%), Кремниевый датчик температуры чипа ESP32 (°C), Использование памяти SRAM (`44 / 327 KB`).
- **Меню настроек экрана по долгому нажатию** одной и той же кнопки `BOOT` — регулировка яркости подсветки `20 / 40 / 60 / 80 / 100%` с сохранением в энергонезависимую память (NVS). Подробности — в разделе [Управление одной кнопкой](#-управление-одной-кнопкой).
- **100% Автоматическое определение COM-порта:** Приложение сканирует оборудование Windows и определяет порт платки по международному USB Vendor ID (`VID_303A` — Espressif Systems). Работает на любом ПК без ручной настройки.
- **Умная обработка отключения и горячее подключение (Hot-Plug):** При физическом отключении платки из USB-порта трансляция данных **мгновенно останавливается** (без попыток слать данные впустую). Подсказка в трее меняет статус на `Disconnected`, а фоновый поток каждые 2 секунды сканирует USB-порты. При повторном включении платки (даже в другой USB-разъем) связь восстанавливается автоматически!
- **Плавная анимация (Zero-Flicker):** Отрисовка выполняется через off-screen буфер `GFXcanvas16` с атомарным выводом на экран по SPI. Значения круговых шкал интерполируются с фактором `0.18`.
- **Индикация статуса на RGB светодиоде (WS2812):** Динамический цвет индикатора от зелёного (< 55°C) до красного мигающего при перегреве (> 80°C).
- **Нативная утилита Windows:** Не требует Python, .NET или тяжелых зависимостей. Занимает `7.5 МБ` ОЗУ и `< 0.05%` CPU.

## 🎛️ Управление одной кнопкой

Всё управление построено на единственной кнопке `BOOT` (GPIO 9). Экран всегда подсказывает, что делает короткое и что длинное нажатие — строка подсказки находится в нижней панели.

| Где вы находитесь | Короткое нажатие (**TAP**) | Долгое нажатие (**HOLD**, 0.7 сек) |
| :--- | :--- | :--- |
| **Дашборд (шкалы)** | Следующая страница `P1 → P2 → P3` | Открыть **Display Settings** |
| **Меню настроек** | Яркость `20 → 40 → 60 → 80 → 100 → 20%` | Сохранить и выйти |

### Как это сделано удобным

- **Индикатор удержания.** Как только вы задерживаете кнопку дольше ~70 мс, внизу экрана ползёт золотая полоса прогресса, а подсказка меняется на `KEEP HOLDING FOR SETTINGS`. Не нужно угадывать, сколько держать: полоса дошла до конца — меню открылось. Если отпустить раньше — сработает обычное переключение страницы.
- **Живой предпросмотр.** Яркость применяется к подсветке **мгновенно** при каждом нажатии, ещё до сохранения — вы видите результат, а не абстрактное число.
- **Наглядная шкала.** Уровень показан пятью сегментами с подписями `20 40 60 80 100`, активный сегмент обведён белой рамкой. Иконка солнца увеличивает длину лучей вместе с яркостью.
- **Невозможно «застрять» в меню.** Если ничего не нажимать, меню само сохранит значение и закроется через 10 секунд. Обратный отсчёт виден справа внизу (`10s … 1s`) и продублирован тонкой полосой над нижней панелью.
- **Настройка переживает перезагрузку.** Значение хранится в NVS (namespace `pcmon`, ключ `bright`) и восстанавливается в `setup()`. Запись в флеш происходит **только если значение реально изменилось** — ресурс флеш-памяти не расходуется впустую.
- **Меню доступно всегда**, даже когда ПК не подключён и на экране висит `WAITING FOR PC`.

### Технические параметры

| Параметр | Константа в скетче | Значение |
| :--- | :--- | :--- |
| Порог долгого нажатия | `BTN_HOLD_MS` | `700` мс |
| Программный антидребезг | `BTN_DEBOUNCE_MS` | `30` мс |
| Автозакрытие меню | `SETTINGS_TIMEOUT_MS` | `10000` мс |
| Уровни яркости | `BRIGHTNESS_LEVELS[]` | `{20, 40, 60, 80, 100}` % |
| Яркость по умолчанию | `BRIGHTNESS_DEFAULT_IDX` | `3` (80%, ≈ прежним `190/255`) |

Проценты отображаются линейно в скважность ШИМ (`duty = pct * 255 / 100`), поэтому число на экране соответствует реальной скважности подсветки.

## 🛠️ Аппаратные характеристики и Pinout

| Компонент | Вывод ESP32-C6 | Примечание / Настройка |
| :--- | :--- | :--- |
| **LCD MOSI** | `GPIO 6` | SPI Data |
| **LCD SCLK** | `GPIO 7` | SPI Clock (Частота **27 MHz**) |
| **LCD MISO** | `GPIO 5` | SPI MISO |
| **LCD CS** | `GPIO 14` | Chip Select |
| **LCD DC** | `GPIO 15` | Data / Command |
| **LCD RST** | `GPIO 21` | Hardware Reset |
| **LCD BL** | `GPIO 22` | Backlight PWM, регулируется из меню (`51…255` = 20…100%), значение хранится в NVS |
| **BOOT Button** | `GPIO 9` | Активный LOW, `INPUT_PULLUP` (TAP — страницы, HOLD — меню настроек) |
| **RGB LED** | `GPIO 8` | WS2812 (**Порядок байт GRB**: `neopixelWrite(8, g, r, b)`) |

## 📡 Протокол передачи данных по USB Serial

Нативное приложение передает строку пакета с разделителями `;` на частоте 2.5 Гц (каждые 400 мс) со скоростью **115200 baud**:

```text
CPU:<0-100>;RAM:<0-100>;TEMP:<C>;GPU:<0-100>;GPUTEMP:<C>;VRAM:<0-100>\n
```

*Пример пакета:*
```text
CPU:16;RAM:36;TEMP:53;GPU:8;GPUTEMP:47;VRAM:18
```

## 🚀 Нативное приложение Windows (`PC_Monitor_Tray.exe`)

Готовое приложение [`PC_Monitor_Tray.exe`](PC_Monitor_Tray.exe) лежит в папке проекта — его можно скачать и запустить без установки компилятора. Исходники — в [`tray_app/`](tray_app/), пересборка описана в разделе [Сборка проекта из исходников](#-сборка-проекта-из-исходников).

### Функция правого клика по иконке в трее (у часов):
- **`▶ Streaming Active / ⏸ Paused`** — Мгновенный запуск и пауза трансляции.
- **`🔌 Select COM Port ▶`** — Динамический список портов. Автоматически найденный порт ESP32 пометятся звёздочкой (`COM12 ★ (ESP32 Auto-Detected)`).
- **`⚙ Run automatically on Windows startup`** — Включение / выключение автозапуска в реестре Windows (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`).
- **`❌ Exit Monitor`** — Выход из программы.

## ⚠️ Важные технические нюансы разработки

### 1. Обязательный флаг компиляции `CDCOnBoot=cdc`
По умолчанию ядра ESP32-C6 направляют вывод `Serial` на внешние выводы UART0. Чтобы `Serial` работал через встроенный USB-Serial/JTAG контроллер микросхемы, **обязательно** компилировать с флагом `CDCOnBoot=cdc`:
```powershell
arduino-cli compile --fqbn esp32:esp32:esp32c6:CDCOnBoot=cdc "J:\ESP32\PC_Hardware_Monitor_ESP32C6"
arduino-cli upload -p COM12 --fqbn esp32:esp32:esp32c6:CDCOnBoot=cdc "J:\ESP32\PC_Hardware_Monitor_ESP32C6"
```

### 2. Порядок каналов WS2812 RGB LED (GRB)
На плате Waveshare ESP32-C6-LCD-1.47 установлены светодиоды WS2812 с аппаратным порядком байт **GRB** (Green-Red-Blue).
При вызове функции `neopixelWrite(PIN_RGB_LED, r, g, b)` цвет выводится неверно. Используется обертка:
```cpp
void setRgbLed(uint8_t r, uint8_t g, uint8_t b) {
  neopixelWrite(PIN_RGB_LED, g, r, b); // Обмен байт Red и Green
}
```

### 3. Экранирование путей Win32 в C++ (`CreateFileW`)
При вызове системного вызова открытия COM-порта в Win32 API адрес должен передаваться в формате `\\.\COM12`. В строковых литералах C++ с поддержкой Unicode вызов выглядит так:
```cpp
swprintf(fullPortPath, 64, L"\\\\.\\%ls", portName);
```

### 4. Внутренний датчик температуры ESP32-C6
В ядре ESP32 v3.3+ (ESP-IDF v5) функция получения температуры кремния имеет имя `temperature_sensor_get_celsius`:
```cpp
temperature_sensor_get_celsius(temp_handle, &tsens_out);
```

## 📦 Сборка проекта из исходников

### Структура папки проекта

| Путь | Назначение |
| :--- | :--- |
| `PC_Hardware_Monitor_ESP32C6.ino` | Прошивка платы (Arduino-скетч) |
| `tray_app/` | Исходники нативного приложения Windows: `pc_monitor_tray.cpp`, `resource.rc`, `app_icon.ico` |
| `host_python/` | Альтернативный хост на Python (`pc_monitor_sender.py`) и папка `lhm/` для LibreHardwareMonitor |
| `PC_Monitor_Tray.exe` | Собранное приложение (хранится в репозитории, пересобирается из `tray_app/`) |
| `pc_monitor_config.ini`, `pc_monitor_debug.log` | Создаются приложением рядом с `.exe`, специфичны для машины (в `.gitignore`) |

Файлы `.cpp` и `.h` лежат в подпапке `tray_app/` намеренно: Arduino IDE компилирует все исходники из корня папки скетча, и хост-приложение Windows попало бы в сборку прошивки.

### Сборка C++ приложения (MinGW `g++`):
```powershell
cd J:\ESP32\PC_Hardware_Monitor_ESP32C6\tray_app
windres resource.rc -O coff -o resource.o
g++ -O2 -mwindows -municode -o ..\PC_Monitor_Tray.exe pc_monitor_tray.cpp resource.o -lkernel32 -luser32 -lgdi32 -lshell32 -ladvapi32
```

### Запуск Python-хоста (опционально):
```powershell
pip install psutil pyserial pythonnet
# Распакуйте LibreHardwareMonitor в host_python\lhm\ (https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases)
python J:\ESP32\PC_Hardware_Monitor_ESP32C6\host_python\pc_monitor_sender.py
```
Папка `lhm/` не хранится в репозитории (~5 МБ, включает подписанный драйвер ядра) — скачайте релиз LibreHardwareMonitor и положите его содержимое туда. Для доступа к датчикам скрипт нужно запускать от имени администратора.

```powershell

& "C:\Users\Constantine\AppData\Local\Programs\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe" upload -p COM12 --fqbn esp32:esp32:esp32c6:CDCOnBoot=cdc "J:\ESP32\PC_Hardware_Monitor_ESP32C6"
```
